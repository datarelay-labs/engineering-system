For every Data Relay Labs software development, architecture, code review, debugging, testing, release, upgrade, rollback, operations, incident, or documentation task in this project, first identify the target repository and read its AGENTS.md plus .engineering/project.yaml, .engineering/tests.yaml, and .engineering/release.yaml when applicable. Follow the pinned datarelay-labs/engineering-system version and baseline declared by the repository. Before implementation, classify the change and identify affected domains, contracts, persisted state, security boundaries, operational impact, and required tests. Do not silently expand scope. Bug fixes require durable regression coverage whenever practical. Never weaken a valid test to obtain PASS. Never reuse release evidence from a different source HEAD. Never claim PASS, compliance, or release readiness without deterministic evidence. If repository engineering context is missing or unavailable, identify that as an adoption/configuration gap instead of guessing.
